# Edits to vendored upstream files

`src/specmatching/` below `spec_matching/` is vendored PyMatching, renamed. Everything under
`src/specmatching/spec_matching/`, `tests/spec_matching/` and `benchmarks/spec_matching/` is ours
and is not listed here.

This file exists so that "which lines are ours" stays answerable by path alone, for the licence, for
the paper, and for anyone who ever wants to diff this fork against upstream again. **Every edit to a
file outside `spec_matching/` gets a row.**

Nine vendored files are touched. The trade taken throughout is *fewer mutation sites*, not fewer
files: liveness is maintained inside `Arena<T>`, which is the single funnel both allocations and
deallocations already pass through, rather than at the seven `add_match` / `Match::clear` sites in
`mwpm.cc` a literal reading would need. It is the call-site count, not the file count, that the
silent-failure risk scales with.

| File | Edit | Why |
|---|---|---|
| `sparse_blossom/tracker/queued_event_tracker.h` | `set_desired_event` gains `cumulative_event_time` and `horizon` arguments, both defaulted so existing call sites are unchanged; adds the `pm::NO_HORIZON` sentinel and the debug-only `pm::horizon_gate_stats` counters | This is the funnel every scheduled event passes through, so it is the one place a horizon gate can guarantee that nothing past `T` is *inserted* rather than inserted and later skipped. The cumulative time has to come from the caller: `ev.time` is a `cyclic_time_int` and cannot be ordered against a cumulative bound |
| `sparse_blossom/flooder/graph_flooder.h` | Adds the `cumulative_time_int horizon` field, initialised to `pm::NO_HORIZON` | The flooder is what the scheduling sites have in hand; the sentinel means the stock path never observes a finite horizon |
| `sparse_blossom/flooder/graph_flooder.cc` | Passes the horizon at the three node-event scheduling sites (`reschedule_events_at_detector_node`, both sites in `do_look_at_node_event`); leaves `schedule_tentative_shrink_event` un-gated; copies `horizon` in the move constructor | Each site carries a one-line comment saying gate-or-exempt and why. Shrink events are exempt so that a shrinking region's shell-area bookkeeping can always complete |
| `sparse_blossom/flooder/graph_flooder.cc` | `run_until_next_mwpm_notification` stops and reports `NO_EVENT` once `queue.cur_time > horizon` | Consequence of the shrink exemption. Exempt shrink events *can* be scheduled past `T`, and processing one would carry the timeline — and therefore every surviving dual — past the horizon, breaking `Y(u) == T`. With the sentinel horizon the comparison is never true, and the stock-path perf gate is green |
| `sparse_blossom/flooder/graph_flooder.h` | Adds `pm::BlossomFormationStats` and the process-wide `pm::blossom_formation_stats` counter | The eager-cached-base option is worth its field only if blossom formations are much rarer than base readouts, and that ratio is not recoverable after the fact — a blossom that forms and then shatters leaves nothing to count. Follows the `pm::horizon_gate_stats` precedent, except that this one is live in release builds, because the measurement it feeds is a release measurement |
| `sparse_blossom/flooder/graph_flooder.cc` | `create_blossom` increments `blossom_formation_stats.formations` | The one place a blossom is created. One increment, against a formation that already sweeps the blossom's whole area to reschedule events |
| `sparse_blossom/driver/mwpm_decoding.{h,cc}` | The detection-event/negative-weight preamble of `process_timeline_until_completion` is factored out into `pm::begin_timeline`, which it now calls, and which the header declares | The truncated timeline reuses the preamble verbatim rather than copying it. `process_timeline_until_completion`'s behaviour is unchanged |
| `sparse_blossom/driver/mwpm_decoding.{h,cc}` | The edge-expansion tail of `decode_detection_events_to_edges` — flip each match edge's shortest path on the search graph, add the graph's negative-weight edges, drop everything flipped an even number of times — is factored out into `pm::expand_match_edges_to_edges` | The spec-matching driver's **oracle** front end has to turn match edges into `G` edges after a *truncated* timeline, so it cannot call the completed-decode entry point. Copying the tail instead would have put the cancellation pass in two places, and the cancellation is the part of it with no independent check on it. Follows the `begin_timeline` precedent exactly: factor out, do not copy. `decode_detection_events_to_edges`'s behaviour is unchanged, and its own tests still cover it |
| `sparse_blossom/driver/mwpm_decoding.{h,cc}` | Adds `pm::CompletionStatus` and `pm::process_timeline_until_completion_or_report`, and reimplements `process_timeline_until_completion` as a call to it followed by the `reset` + throw | The stock-on-`H` front end runs *stock* blossom on `H` and treats "no perfect matching in `H`" as a valid escalation trigger rather than an error, so it needs the completion loop without the throw. Factored rather than copied: there is still one timeline loop and one tree-survival test in the tree. The reporting form deliberately does **not** call `Mwpm::reset` — the caller owns the teardown, and the certificate has to inspect the terminal dual before anything is torn down. `process_timeline_until_completion`'s behaviour, including the exception type and message, is unchanged, and the radix heap and the timeline loop itself are untouched |
| `sparse_blossom/arena.h` | Adds the `pm::arena_tracks_live<T>` trait, a `std::vector<T *> live` of the currently checked-out objects maintained by swap-remove, `alloc_constructed(Args&&...)`, and the link/unlink calls in `alloc_default_constructed` and `del`. Also empties `live` by move in `~Arena` rather than by `clear()`. Every use is behind `if constexpr`, so arenas of types that do not opt in are unchanged | Harvest needs to enumerate the live `AltTreeNode`s and `GraphFillRegion`s without traversing the structures they form. The arena is the **single funnel** every allocation and deallocation of both types already passes through, so the list cannot be left stale by a missed mutation site — the one failure mode that would be silent. Linking has to happen after construction (a placement-new would clobber the slot), which is why `alloc_constructed` exists rather than a hook inside `alloc_unconstructed`. The destructor detail is not cosmetic: `Mwpm::reset()` destructs the arena explicitly and then lets it be destructed again, which the pre-existing members survive only because they are moved-from — a `clear()` keeps the capacity and double-frees on the second pass (caught by ASan in `MwpmDecoding.NoValidSolutionForLineGraph`) |
| `sparse_blossom/matcher/alternating_tree.h` | Adds one `uint32_t arena_live_index = pm::ARENA_NOT_LIVE` to `AltTreeNode`, with a default member initializer | Declaring it is what opts the type into the arena's liveness tracking, and it is the slot swap-remove needs to make removal O(1). **Not** a pointer pair: `prev`/`next` grew `AltTreeNode` from 104 bytes to 128 and `GraphFillRegion` from 128 to 152, and that cost a consistent 2–4% of the stock decode path in cache footprint alone, failing the perf gate. The single slot lands in padding both structs already had, so both are byte-for-byte their previous size. A vector is also the better shape for what the list is *for* — enumeration is a linear scan of contiguous pointers, not a chase. Nothing in the matcher reads or writes the field, and no constructor mentions it |
| `sparse_blossom/flooder/graph_fill_region.h` | The same field on `GraphFillRegion`, declared at offset 44 between `shrink_event_tracker` and `match` | The alternative — appending to a maintained list of top-level matched regions at the match sites — needs edits at seven sites in `mwpm.cc` (four `add_match` calls, the direct boundary match, and the two `Match::clear`s in `handle_tree_hitting_match`), and a missed one is silent. Tracking *every* region instead reduces "top-level" to one local `blossom_parent == nullptr` test, costs no mutation sites at all, and additionally turns `dual_sum_at_truncation` from a descent through blossom nesting into a flat reduction. The declaration position is load-bearing — that hole is the existing padding the field has to land in, so do not tidy it to the bottom of the struct |
| `sparse_blossom/matcher/mwpm.cc` | `make_child` and `create_detection_event` allocate through `node_arena.alloc_constructed(...)` instead of `alloc_unconstructed()` followed by a placement-new | The two sites where an `AltTreeNode` comes into existence. Behaviourally identical; it exists so the arena can install the liveness link once the object's lifetime has begun |
| `specmatching.pybind.cc` | Includes `spec_matching/driver/spec_matching.pybind.h` and calls `pm_pybind::pybind_spec_matching(m)` | The module's registration list is the one place a new binding can be attached. Two lines, following the `pybind_rand_gen_methods` pattern already there |
| `__init__.py` | Re-exports `SpecMatchingConfig`, `SpecMatchingDecoder`, `SpecMatchingAggregateStats`, `summarize` and `spec_matching_decoder` | Additive; the inherited `Matching` export and the `randomize()` call are untouched. The python helper itself is a new file, `_spec_matching.py`, and is *not* named `spec_matching.py`: that would sit beside the `spec_matching/` C++ source directory inside the same package and make `specmatching.spec_matching` ambiguous |
| `README.md` | Adds a "spec-matching decoder" section with a usage example, the horizon/memory trade, and the measured latency against stock | The attribution section, the sparse-blossom citation and every URL are untouched (`check_vendor.sh` gate 2 still applies). The number is in the README rather than only in the latency report because it is the first thing a reader assumes the opposite of |
| `CMakeLists.txt` | Adds the `spec_matching/` sources to `SOURCE_FILES_NO_MAIN`, the `tests/spec_matching/` suites to `TEST_FILES`, `spec_matching/driver/spec_matching.pybind.cc` to `PYTHON_API_FILES`, the repo root to the test and benchmark include paths, `-UNDEBUG` on the test target, and the `sparse_graph_stats`, `component_profiler` and `load_balancer_profiler` targets | The file enumerates sources explicitly, so new files have to be listed. `-UNDEBUG` keeps the debug-build invariants (asserts, horizon gate counters) live in the test binary even when the tree is configured `Release`. The benchmark targets get the repo root on their include path because they include `benchmarks/spec_matching/profiler_util.h`, which is outside the `src` include root |

## Not edited, deliberately

- The `pm` / `pm_pybind` namespaces are untouched, as the design requires. New code lives in
  `pm::spec_matching`.
- `sparse_blossom/matcher/mwpm.{h,cc}` is otherwise untouched. `shatter_exposed_blossom_and_extract_matches`
  is a *sibling* of the upstream shatter routines, in `spec_matching/truncation/exposed_blossom.cc`,
  rather than a modification of them.
- `sparse_blossom/ints.h` is untouched. `pm::NO_HORIZON` went into `queued_event_tracker.h`, which
  was already being edited, rather than opening another vendored file.
